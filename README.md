# Bookstore API

REST API для книжкового магазину: керування інвентарем книг, обробка покупок і відстеження замовлень клієнтів. Практична робота №4 з дисципліни «Якість програмного забезпечення та тестування».

Проєкт написано на **FastAPI**. Дані зберігаються **в пам'яті** процесу (без бази даних), тому після перезапуску сервера вони очищаються. API покрито **46 юніт-тестами** (`unittest` + `TestClient`), а також перевірено вручну через **Postman**.

## Можливості

- **Інвентар книг:** додавання, отримання (одна або всі), часткове оновлення, видалення за ID або за ISBN.
- **Покупки:** створення замовлення перевіряє наявність книги й зменшує її кількість на складі.
- **Замовлення:** отримання за ID, зміна статусу (`processing` → `shipped` → `completed`).
- **Замовлення клієнта:** перегляд усіх замовлень за ID клієнта.
- **Захист даних:** унікальний ISBN, заборона зміни ISBN, перевірка від'ємних значень, заборона покупки більшої кількості, ніж є на складі.

## Встановлення

Потрібен Python 3.10 або новіший. Усі команди виконуються з кореня проєкту (папка `lab4`).

**Windows (PowerShell):**

```
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

Якщо PowerShell забороняє активацію скриптів, виконайте один раз:

```
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

**Linux / macOS:**

```
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Після активації перед шляхом у терміналі з'явиться `(venv)`.

Якщо `requirements.txt` відсутній або потрібно оновити його:

```
pip install fastapi uvicorn httpx
pip freeze > requirements.txt
```

## Запуск сервера

```
uvicorn app.main:app --reload
```

- Сервер: http://127.0.0.1:8000
- Прапорець `--reload` перезапускає сервер при зміні `.py` файлів. **Під час перезапуску дані в пам'яті зникають.**
- Зупинити сервер: `Ctrl+C`.
- Запускати слід саме через `uvicorn`, а не кнопкою «Run» у редакторі: файл `main.py` лише описує застосунок.

Перевірка, що сервер працює: відкрийте http://127.0.0.1:8000/ , має повернутись `{"message": "ok"}`.

## Опис ендпоінтів

Усі запити й відповіді мають формат JSON. Базова адреса: `http://127.0.0.1:8000`.

| Метод | Ендпоінт | Опис |
|---|---|---|
| POST | `/books/` | додати книгу |
| GET | `/books/` | усі книги |
| GET | `/books/{id}` | книга за ID |
| PUT | `/books/{id}` | оновити ціну, кількість, опис |
| DELETE | `/books/{id}` | видалити книгу за ID |
| DELETE | `/books/isbn/{isbn}` | видалити книгу за ISBN |
| POST | `/orders/` | створити замовлення (покупка) |
| GET | `/orders/{id}` | замовлення за ID |
| PUT | `/orders/{id}/status` | змінити статус замовлення |
| GET | `/customers/{id}/orders` | усі замовлення клієнта |

### Книги

#### POST `/books/` — додати книгу

Тіло запиту:

```json
{
  "isbn": "123",
  "title": "Kobzar",
  "author": "Taras Shevchenko",
  "price": 150,
  "quantity": 10,
  "description": "Poetry"
}
```

| Поле | Тип | Обов'язкове | Обмеження |
|---|---|---|---|
| `isbn` | рядок | так | не порожній, унікальний |
| `title` | рядок | так | не порожній |
| `author` | рядок | так | не порожній |
| `price` | число | так | ≥ 0 |
| `quantity` | ціле | так | ≥ 0 |
| `description` | рядок | ні | — |

Відповідь `201 Created`:

```json
{
  "isbn": "123",
  "title": "Kobzar",
  "author": "Taras Shevchenko",
  "price": 150.0,
  "quantity": 10,
  "description": "Poetry",
  "id": 1
}
```

| Код | Коли |
|---|---|
| 201 | книгу додано, їй присвоєно `id` |
| 409 | книга з таким ISBN вже існує |
| 422 | порушено валідацію (від'ємна ціна чи кількість, немає обов'язкового поля) |

#### GET `/books/` — усі книги

Відповідь `200 OK`: масив книг. Якщо інвентар порожній, повертається `[]`.

#### GET `/books/{id}` — книга за ID

Відповідь `200 OK`: об'єкт книги (як вище). Якщо книги немає, `404 Not Found`:

```json
{"detail": "Книгу не знайдено"}
```

#### PUT `/books/{id}` — оновити книгу

Можна передати будь-яке з полів `price`, `quantity`, `description`. Передані поля змінюються, решта лишається як була.

```json
{"price": 200, "quantity": 20}
```

| Код | Коли |
|---|---|
| 200 | оновлено, у відповіді повна книга |
| 400 | не передано жодного поля для оновлення (порожнє тіло `{}`) |
| 404 | книги з таким ID немає |
| 422 | від'ємна ціна чи кількість, або передано заборонене поле (наприклад, `isbn`) |

> **ISBN змінювати не можна.** Модель оновлення не містить поля `isbn` і відхиляє будь-які зайві поля, тому запит `{"isbn": "000"}` завершується помилкою `422` (`extra_forbidden`), а ISBN книги лишається старим.

#### DELETE `/books/{id}` та DELETE `/books/isbn/{isbn}` — видалити книгу

Відповідь завжди `200 OK`, навіть якщо книги не було:

```json
{"deleted": true, "message": "Книгу видалено"}
```

```json
{"deleted": false, "message": "Книги не було в інвентарі"}
```

Видалення неіснуючої книги не викликає помилки (вимога завдання). Чи видалено книгу реально, показує поле `deleted`.

### Замовлення та покупки

#### POST `/orders/` — створити замовлення

Створення замовлення **є покупкою**: сервер перевіряє наявність, зменшує кількість книги на складі й повертає суму.

```json
{"customer_id": 1, "isbn": "123", "quantity": 2}
```

| Поле | Тип | Обмеження |
|---|---|---|
| `customer_id` | ціле | ≥ 1 |
| `isbn` | рядок | не порожній, книга з таким ISBN має існувати |
| `quantity` | ціле | ≥ 1 |

Відповідь `201 Created`:

```json
{
  "id": 1,
  "customer_id": 1,
  "isbn": "123",
  "title": "Kobzar",
  "quantity": 2,
  "total_price": 400.0,
  "status": "processing"
}
```

`total_price` = ціна книги × кількість. Початковий статус завжди `processing`.

| Код | Коли |
|---|---|
| 201 | замовлення створено, кількість на складі зменшилась |
| 404 | книги з таким ISBN немає в інвентарі |
| 409 | запитано більше, ніж є на складі (`"Запитано 999, на складі лише 18"`) |
| 422 | кількість 0 або від'ємна, немає `customer_id` чи інших полів |

При помилці склад не змінюється й замовлення не створюється. Купити можна рівно стільки, скільки є на складі (залишиться 0).

#### GET `/orders/{id}`

Відповідь `200 OK`: об'єкт замовлення. Якщо замовлення немає, `404 Not Found`.

#### PUT `/orders/{id}/status` — змінити статус

```json
{"status": "shipped"}
```

Допустимі значення: `processing` (на обробці), `shipped` (відправлено), `completed` (виконано).

Статуси змінюються **лише вперед і по одному кроку**:

```
processing  →  shipped  →  completed
```

| Код | Коли |
|---|---|
| 200 | статус змінено, у відповіді повне замовлення |
| 404 | замовлення немає |
| 409 | спроба пропустити крок (`processing` → `completed`), повернутись назад або повторити поточний статус |
| 422 | невідоме значення статусу (наприклад, `"flying"`) |

#### GET `/customers/{id}/orders` — замовлення клієнта

Відповідь `200 OK`: масив усіх замовлень клієнта з поточними статусами. Замовлення інших клієнтів не включаються. Якщо замовлень немає, повертається `[]`.

### Формат помилок

Помилки бізнес-логіки (404, 409, 400) мають вигляд:

```json
{"detail": "Книга з таким ISBN вже існує"}
```

Помилки валідації (422) формуються FastAPI й містять тип, місце й опис проблеми:

```json
{
  "detail": [
    {
      "type": "extra_forbidden",
      "loc": ["body", "isbn"],
      "msg": "Extra inputs are not permitted",
      "input": "000"
    }
  ]
}
```

### Приклад сценарію (curl)

```
# 1. Додати книгу
curl -X POST http://127.0.0.1:8000/books/ -H "Content-Type: application/json" \
  -d '{"isbn":"123","title":"Kobzar","author":"Taras Shevchenko","price":150,"quantity":10}'

# 2. Купити 2 примірники
curl -X POST http://127.0.0.1:8000/orders/ -H "Content-Type: application/json" \
  -d '{"customer_id":1,"isbn":"123","quantity":2}'

# 3. Змінити статус
curl -X PUT http://127.0.0.1:8000/orders/1/status -H "Content-Type: application/json" \
  -d '{"status":"shipped"}'

# 4. Переглянути замовлення клієнта
curl http://127.0.0.1:8000/customers/1/orders
```

У Windows PowerShell краще використовувати Postman або Swagger (`/docs`), бо `curl` там є псевдонімом іншої команди й інакше обробляє лапки.

## Правила та валідація

| Ситуація | Поведінка |
|---|---|
| Додавання книги з наявним ISBN | 409, книга не додається |
| Зміна ISBN через PUT | 422, ISBN не змінюється |
| Оновлення або отримання неіснуючої книги | 404 |
| Видалення неіснуючої книги | 200, `deleted: false` |
| Покупка неіснуючої книги | 404 |
| Покупка більшої кількості, ніж є | 409, склад не змінюється |
| Кількість у замовленні ≤ 0 | 422 |
| Одне замовлення | містить одну книгу (`isbn` + `quantity`) |
| Зміна статусу | лише на наступний крок, інакше 409 |
| ID книг і замовлень | цілі числа від 1, після видалення не використовуються повторно |
| Клієнт без замовлень | порожній список, не помилка |

## Тести

Використовується модуль `unittest` і `fastapi.testclient.TestClient`. Перед кожним тестом у `setUp` викликається `storage.reset()`, тому тести незалежні один від одного й не потребують запущеного сервера.

### Запуск усіх тестів

З кореня проєкту (`lab4`), з активованим `venv`:

```
python -m unittest discover -s tests -t . -v
```

Очікуваний результат:

```
Ran 46 tests in ...s

OK
```

### Запуск окремих тестів

```
# один файл
python -m unittest tests.test_books -v

# один клас
python -m unittest tests.test_orders.TestOrderStatus -v

# один тест
python -m unittest tests.test_books.TestCreateBook.test_duplicate_isbn_rejected -v
```

### Що покрито

| Файл | Тестів | Що перевіряє |
|---|---|---|
| `tests/test_books.py` | 19 | створення (дубль ISBN, валідація), отримання, оновлення (ISBN не змінюється, часткове оновлення), видалення за ID та ISBN, видалення неіснуючої книги |
| `tests/test_purchases.py` | 11 | успішна покупка, сума, зменшення складу, покупка всього запасу, відмова при нестачі чи відсутній книзі, нульова й від'ємна кількість |

## Тестування в Postman

Файл `postman_collection.json` містить колекцію **Bookstore API**.

1. Запустіть сервер (`uvicorn app.main:app --reload`).
2. У Postman: **Import** → оберіть `postman_collection.json`.
3. Виконуйте запити по порядку: Add book → Get all books → Get book → Update book → Create order → Get order → Update status → Customer orders → Get book (після покупки кількість зменшилась) → запити з помилками (дубль ISBN, замовлення більшої кількості, зміна ISBN) → Delete book.

Для запитів із тілом має бути вибрано **Body → raw → JSON**. Колекція очікує, що книга з ISBN `123` створена запитом Add book; якщо сервер перезапускався, почніть із нього знову.

## Обмеження

- Сховище в пам'яті: дані не зберігаються між перезапусками сервера.
- Немає автентифікації: `customer_id` просто число, окремої сутності клієнта немає.
- Одне замовлення містить одну книгу.
- Немає пошуку книг і рейтингів (вони були в ПР3 у класі `Bookstore`, у цій роботі не переносились).
- Один процес: стан не синхронізується між кількома воркерами.

## Типові проблеми

| Проблема | Рішення |
|---|---|
| `No module named 'fastapi'` | не активовано `venv` або не виконано `pip install -r requirements.txt` |
| `uvicorn` не розпізнається | `venv` не активовано, запустіть `venv\Scripts\activate` |
| `ModuleNotFoundError: No module named 'app'` | команду запущено не з кореня `lab4` |
| Активація `venv` заборонена в PowerShell | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| Postman: `Could not get any response` | сервер не запущено; перевірте http://127.0.0.1:8000/docs |
| 404 на книгу, яку щойно додали | сервер перезапустився (збережено `.py` файл), дані зникли, додайте книгу знову |
| `Address already in use` | порт 8000 зайнятий; зупиніть старий сервер або запустіть з `--port 8001` |
